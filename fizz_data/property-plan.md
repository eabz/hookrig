## Implementation notes
- GL-02 asserts `>=`. The strict-equality form (no stranded 6909) is not asserted; if wanted, log the surplus with `Logger` for review.
- SP-04 counts the actor's own `poolClaims` gained in currency A as received value, because on POOL_MULTI actors[1] and actors[2] are tax and fee-share recipients.
- SP-05 / SP-06 skip the assertion when the buy graduates the curve (sell is disabled after graduation).
- SP-11 only applies on POOL_XYK exact-output sells, where the 100 bps tax is the only claim slice. The equality also holds when `grossIn * 100` is a multiple of 1e4, so no skip is needed.
- SP-21 must exit with the same route mode used to add (from `lpAddRoute`), otherwise SP-16's bug can mask the liveness check.
- GL-16 skips orders on `nativeOrderKey` (never initialized, so it never crosses) and orders placed before the pool had `BIT_LIMIT_ORDERS`.
- Dropped as redundant or cosmetic after merging: VT-03, VS-04 (King pot monotone / king ⇒ pot; covered by GL-02, GL-03, GL-08), VT-05 (order id ordering), VT-06 (accumulator monotonicity), VS-03, ST-04, ST-09, VT-04 (bucket state machine; GL-20 and SP-03 assert the value side), ST-12, ST-14, ST-23, CON-12 / VS-05 / SPEC-18 (swap-points sum), CON-19, CON-20 / VS-11, RD-03b, RD-06, RD-11, RT-02, SPEC-13 supply bound.
